## Per-island census (`per_island/`)

209 CSV files, one per island (plus one "non-admin islands" row per atoll). Each file holds a single
2022 row (`reference_year`) of aggregate counts: population by sex, age bands (0–17, 18–64, 65+),
disability counts, elderly living alone, plus `island_code`, `atoll_code` and coordinates. The
`residence_basis` is `usual_residence`. File names are `{island_code:05d}_{atoll}_{island}.csv`.

Note: the census `island_code` and coordinates come from this census extract. The ferry tables do not
yet link to them, so ferry `stops.csv` keeps those fields blank.

The source PDFs for the ferry extraction are not committed. Place them in the repository root to rerun it.

## Ferry timetables

Published Maldives ferry timetables (the PDFs in this folder) extracted into CSVs for multi-leg journey
planning, connectivity analysis and disruption simulation. These are **published schedules**, not evidence
that trips operated, and not confirmation that a schedule is current.

- Outputs: `data/processed/ferry/*.csv`
- Column definitions and controlled values: [docs/ferry_data_dictionary.md](docs/ferry_data_dictionary.md)
- Method, coverage, version decisions and open issues: [docs/ferry_extraction_report.md](docs/ferry_extraction_report.md)
- Reviewed decisions (aliases, Dhivehi readings, calendar annotations): `data/manual/ferry/`
- Audit evidence (raw text, coordinate rows, coverage, version diffs, validation report): `data/interim/ferry/`

### Rerun

Python 3.12, offline, no API keys. The source PDFs are read, never modified.

```bash
pip install -r requirements.txt

# extract all PDFs, write CSVs + interim evidence, then validate (exit code 1 if any check fails)
python scripts/extract_ferry_schedules.py

# validate existing CSVs only
python scripts/extract_ferry_schedules.py --validate-only

# also re-render every page to PNG for visual review (data/interim/ferry/renders/)
python scripts/extract_ferry_schedules.py --render

# tests (parsers, normalisation, end-to-end policy checks; ~4 minutes)
python -m pytest tests -q
```

On Windows consoles that are not UTF-8, prefix Python with `-X utf8` (for example
`python -X utf8 scripts/extract_ferry_schedules.py`).

### Alif atolls (AA, ADh) ↔ Malé subset

```bash
python scripts/build_alif_male_subset.py   # reads data/processed/ferry, run after the extraction
```

Writes `data/processed/ferry/subsets/`:

- `alif_male_direct.csv`: every published trip that carries you between an AA/ADh island and Malé or
  Hulhumalé without changing ferry. Includes all versions, with `version_status`, `routing_eligible` and
  `exclusion_reasons`. Filter `routing_eligible = 1` for the current-candidate timetable. `direction` is
  `to_male` or `from_male`.
- `alif_male_one_transfer.csv`: journeys with one change, built only from routing-eligible trips. The
  connections are **derived**, not published: same island, shared weekday, onward ferry not earlier than
  arrival. Minimum transfer time and landing jetty are unknown (see the `notes` column).

### Using the data for routing

Join `trips` to `routing_eligibility` and keep `routing_eligible = 1`. Everything else stays in the
tables for analysis but is excluded by default (historical/duplicate/unresolved versions, departure-only
lists, cargo, unanchored alternating weeks, unresolved stop identities, rows with source errors).
Times are clock times in the declared project timezone **Asia/Male** (an assumption; the PDFs do not
state a timezone), with `*_day_offset` and `*_seconds` measured from the start of the service day.

## FollowMe GPS cleaning (private)

The end-to-end local pipeline cleans every FollowMe CSV/ZIP observation nationally, then selects
complete continuity segments intersecting AA, ADh, K, V and Greater Malé. Reviewed Government of
Maldives/OCHA COD-AB polygons are supplemented with all 379 OneMap island footprints in scope.
No screenshot labels, island centroids or artificial buffers define the region.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/run_followme_pipeline.py --init-secret --sample-rows 2000 --output data/private/followme_sample
.venv/bin/python scripts/run_followme_pipeline.py
.venv/bin/python scripts/run_followme_pipeline.py --reuse-staging --verify-repeat
.venv/bin/python -m pytest tests/test_followme_pipeline.py -q
```

Keep `data/private/followme.secret` private and reuse it for stable device keys. The input defaults to
`../FollowMe_august_2025/`; national and regional settings are in `config/followme.json` and
`config/followme_region.json`. Every generated observation, lineage, device-day statistic and
trajectory remains private under ignored `data/private/`. No GPS data is uploaded.

See [cleaning method](docs/followme_cleaning.md), [output data dictionary](docs/followme_data_dictionary.md)
and [geographic source review](docs/followme_geography.md). Run-specific reports are
`data/private/followme/cleaning_report.md` and `data/private/followme/regional_cleaning_report.md`.
The latter reports outside-boundary observations retained as members of complete selected segments.

## Harbour and jetty reference

OpenStreetMap harbour/jetty/terminal features (Geofabrik Maldives extract, ODbL) assigned to OneMap islands by polygon or nearest
shoreline, matched to ferry-schedule stops, grouped across sources and compared with GPS-derived stop clusters. OneMap's public layers
contain no harbour layer. Method, licences, thresholds, coverage gaps and the review checklist: [docs/harbour_reference.md](docs/harbour_reference.md).

```bash
.venv/bin/python -m pip install -r requirements.txt                 # adds osmium for the PBF extract
.venv/bin/python scripts/collect_harbour_sources.py                 # network; raw files into data/reference/harbours/raw/ (add --source overpass to try Overpass)
.venv/bin/python scripts/build_harbour_reference.py                 # offline; writes data/reference/harbours/{harbour_reference.geojson,.csv,provenance.json,coverage.json,harbour_reference_review.csv}
.venv/bin/python scripts/build_stop_candidates.py                   # private; exits 2 unless both FollowMe run manifests are complete and valid
.venv/bin/python -m pytest tests/test_harbour_reference.py tests/test_stop_candidates.py -q
```

Settings are in `config/harbour_reference.json` and `config/harbour_stops.json`. Stop and cluster outputs stay under ignored
`data/private/followme/`. A GPS cluster is a candidate only; a terminal is `confirmed` solely by a human in the review CSVs.

## Inferred vessel services (aggregates for the journey planner)

Infers stops, trips, route signatures and regular "inferred services" from the cleaned FollowMe outputs, reusing the slow/fast speed logic of
the vessel pipeline (`../FollowMe_pipeline/`, see [docs/vessel_pipeline_notes.md](docs/vessel_pipeline_notes.md)). Labels are "inferred class"
and "inferred service"; nothing is a confirmed ferry or official timetable. Times are `collection_time` read as local Maldives time
(unconfirmed); the speed unit (knots) is unconfirmed. Method, outputs, limits and approved wording: [docs/vessel_datasets.md](docs/vessel_datasets.md).

```bash
.venv/bin/python scripts/build_vessel_services.py --scope corridor    # Mathiveri, Bodufolhudhoo, Ukulhas, Rasdhoo, Male, Thoddoo, Maafushi
.venv/bin/python scripts/build_vessel_services.py --scope full        # AA, ADh, K, V, Greater Male (inhabited islands + terminal-class jetties)
.venv/bin/python scripts/build_vessel_services.py --scope full --use-cache --skip-sensitivity   # rerun faster (cache stays under data/private/)
.venv/bin/python -m pytest tests/test_vessel_services.py -q
```

Exits unless both FollowMe run manifests are complete and valid. Private outputs (`vessel_classes`, `vessel_trips`, `vessel_journeys`
parquet, device keys) go to `data/private/followme/`; shareable aggregates go to `data/derived/vessels/`. Settings and every provisional
threshold: `config/vessel_services.json`.
